
# Use PostgreSQL

# ADR-001: Adopt PostgreSQL as the Primary Database

- **Status:** Accepted
- **Date:** 2026-08-02
- **Decision Makers:** ShopSphere Development Team

## Context

ShopSphere is being developed as an enterprise-grade e-commerce backend following a modular monolith architecture with a planned migration to microservices in the future.

The application requires a relational database capable of maintaining transactional consistency while supporting complex relationships between business domains such as users, products, inventory, carts, orders, payments, reviews, and coupons.

The selected database should also align with enterprise development practices and integrate seamlessly with the Spring Boot ecosystem.

## Decision

PostgreSQL has been selected as the primary relational database for ShopSphere.

All persistent application data will be stored in PostgreSQL throughout the development of the modular monolith. The same database technology will continue to be used during the transition to a microservices architecture unless a future service has domain-specific storage requirements.

## Alternatives Considered

### MySQL

A widely adopted relational database with strong Spring Boot support.

**Reason not selected**

Although suitable for many applications, PostgreSQL provides a richer feature set that better aligns with the long-term goals of ShopSphere.

### MongoDB

A document-oriented NoSQL database.

**Reason not selected**

The project contains highly relational business domains and requires strong transactional consistency, making a relational database a better fit.

## Consequences

### Positive

- Strong ACID transaction support.
- Excellent support for relational data modeling.
- Well integrated with Spring Data JPA and Hibernate.
- Mature indexing and query optimization capabilities.
- Suitable for future scalability as the application evolves.
- Widely adopted in enterprise backend development.

### Trade-offs

- Requires careful schema design and migration management.
- More structured than document databases, making schema evolution more controlled.
- Complex joins should be designed thoughtfully to maintain performance.
