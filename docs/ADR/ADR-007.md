
# Flyway for Database Migration

# ADR-007: Adopt Flyway for Database Schema Versioning

- **Status:** Accepted
- **Date:** 2026-08-02
- **Decision Makers:** ShopSphere Development Team

## Context

ShopSphere uses PostgreSQL as its primary relational database. As the application evolves, the database schema will undergo continuous changes, including creating new tables, modifying existing structures, adding indexes, and enforcing constraints.

Managing these changes manually is error-prone and makes it difficult to maintain consistency across development, testing, and production environments.

A database migration tool is required to version, automate, and track all schema changes throughout the project's lifecycle.

## Decision

ShopSphere will use **Flyway** for database schema versioning and migration management.

All database schema changes will be maintained as versioned SQL migration scripts within the project repository. Flyway will automatically execute pending migrations during application startup, ensuring that every environment remains synchronized with the expected database schema.

Schema changes will never be performed manually on shared environments.

## Alternatives Considered

### Manual SQL Scripts

Database changes are executed manually using SQL clients.

**Reason not selected**

Manual execution is difficult to track, prone to human error, and cannot guarantee consistency across multiple environments.

### Hibernate Automatic DDL (`ddl-auto`)

Allow Hibernate to create or update the database schema automatically.

**Reason not selected**

Automatic schema generation is convenient during experimentation but provides limited control over schema evolution, lacks version history, and is not recommended for enterprise applications where database changes must be traceable and repeatable.

### Liquibase

A database migration framework supporting SQL, XML, YAML, and JSON changelogs.

**Reason not selected**

Liquibase offers extensive functionality, but Flyway provides a simpler migration model that aligns well with ShopSphere's development workflow and preference for SQL-based schema management.

## Consequences

### Positive

- Maintains a complete version history of database schema changes.
- Ensures consistent database structure across all environments.
- Supports repeatable and automated deployments.
- Simplifies onboarding by allowing developers to recreate the database from migration scripts.
- Provides traceability for every schema modification through version-controlled migration files.

### Trade-offs

- Every schema change requires a new migration script.
- Existing migration scripts should remain immutable once shared.
- Incorrect migration design may require corrective migrations instead of modifying previously executed scripts.
