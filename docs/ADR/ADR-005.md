
# Use UUID Primary Keys

# ADR-005: Use UUIDs as Primary Keys

- **Status:** Accepted
- **Date:** 2026-08-02
- **Decision Makers:** ShopSphere Development Team

## Context

ShopSphere is designed as an enterprise e-commerce backend that will initially be developed as a modular monolith and later evolve into a microservices architecture.

The application contains multiple business domains—including Identity, Product, Inventory, Cart, Order, Payment, Review, and Coupon—that require globally unique identifiers. The primary key strategy should support distributed systems, simplify future service extraction, and avoid identifier collisions across independently managed domains.

## Decision

ShopSphere will use **UUID (Universally Unique Identifier)** as the primary key for all persistent entities.

Each entity will receive a UUID when created, and this identifier will remain immutable throughout the entity's lifecycle.

UUIDs will be used consistently across all business modules to provide a uniform identification strategy.

## Alternatives Considered

### Auto-Increment Integer (IDENTITY)

Sequential numeric identifiers generated by the database.

**Reason not selected**

Although simple and efficient for single-database applications, auto-increment identifiers become more difficult to manage in distributed environments and expose predictable resource identifiers through public APIs.

### Database Sequences

Sequence-based numeric identifiers managed by the database.

**Reason not selected**

Sequences provide reliable identifier generation within a single database but remain database-dependent and offer limited flexibility for future distributed architectures.

## Consequences

### Positive

- Provides globally unique identifiers across all business domains.
- Supports future migration to microservices without changing the identifier strategy.
- Prevents primary key collisions across independently evolving services.
- Makes public resource identifiers difficult to predict.
- Enables consistent identifier generation without relying on database-specific sequences.

### Trade-offs

- UUID values consume more storage than numeric identifiers.
- UUIDs are less human-readable during debugging.
- Indexes on UUID columns may require more storage than integer-based indexes.
